# LTDCE monthly voting guide

## English

The first poll will be announced once voting is set up and at least two ideas are ready. You’ll need a GitHub account to suggest, react, or vote.

1. **Days 1–20 · Share ideas.** Check open suggestions first. If someone already proposed your idea, add 👍 and share what happened in your match. For a new idea, describe the problem and the change you’d like to try. Include the map version, mode and wave when relevant.
2. **Days 21–23 · Shortlist.** The team picks up to five ideas based on community support and whether they’re feasible to test. If fewer than two are ready, the poll moves to the next round. Later ideas stay open for future rounds.
3. **Day 24 to the last day of the month · Vote.** The poll runs on GitHub Discussions until 23:59 Brasília time. The proposed format is one choice per GitHub account.
4. **Early next month · See what happens next.** We publish the totals and which ideas go first. The maintainer follows up with the authors in their GitHub threads to understand the goal, agree on what to test and implement the changes selected for testing. The thread links to the work and, if shipped, the release.

If there’s a tie for first place, the team considers impact on matches and feasibility, then explains the decision publicly. Critical bugs can be fixed at any time. If testing uncovers stability, performance or balance problems, we’ll explain the result and the next step.

**Temporary changes.** Major gameplay or meta changes may have an end date announced in the release notes. Share match feedback in the suggestion thread to help decide whether the change stays, gets revised or ends. A monthly **CHAOS META** mode is a future idea for trying larger changes in a separate mode.

## Русский

Первое голосование объявим, когда настроим его и подготовим хотя бы две идеи. Чтобы предлагать изменения, ставить реакции и голосовать, нужна учётная запись GitHub.

1. **С 1-го по 20-е · Предложения.** Посмотрите открытые идеи. Если вашу идею уже предложили, поставьте 👍 и расскажите о своём матче. Для новой идеи опишите проблему и изменение, которое хотите попробовать. Если это важно, укажите версию карты, режим и волну.
2. **С 21-го по 23-е · Отбор.** Команда выбирает до пяти идей с учётом поддержки игроков и возможности их протестировать. Если готовы меньше двух идей, голосование переносится на следующий цикл. Поздние предложения остаются открытыми для следующих туров.
3. **С 24-го до последнего дня месяца · Голосование.** Опрос в GitHub Discussions открыт до 23:59 по времени Бразилиа. Предлагаемый формат — один вариант на учётную запись GitHub.
4. **В начале следующего месяца · Итоги.** Мы публикуем число голосов и список приоритетных идей. Разработчик связывается с авторами в их темах на GitHub, уточняет цель, согласует условия проверки и реализует выбранные для тестирования изменения. Там же появятся ссылки на работу и на выпуск, если изменение войдёт в него.

При равенстве голосов за первое место команда оценивает влияние на матчи и возможность реализации, а затем публично объясняет выбор. Критические ошибки можно исправлять в любое время. Если тест выявит проблемы со стабильностью, производительностью или балансом, мы опубликуем результат и дальнейшие шаги.

**Временные изменения.** Для крупных изменений игрового процесса или меты дата окончания может быть указана в примечаниях к выпуску. Расскажите о матчах в теме предложения, чтобы помочь решить, оставить изменение, доработать или убрать. Ежемесячный **CHAOS META** — идея на будущее для проверки крупных изменений в отдельном режиме.

## 한국어

투표 설정을 마치고 준비된 아이디어가 두 개 이상이면 첫 투표를 공지합니다. 제안하거나 반응을 남기고 투표하려면 GitHub 계정이 필요합니다.

1. **1~20일 · 아이디어 제안.** 먼저 열린 제안을 살펴보세요. 같은 아이디어가 있다면 👍를 누르고 경기에서 겪은 일을 알려 주세요. 새 아이디어라면 문제와 시험해 보고 싶은 변경 사항을 적어 주세요. 관련이 있다면 맵 버전, 모드, 웨이브도 함께 적어 주세요.
2. **21~23일 · 후보 선정.** 커뮤니티의 지지와 테스트 가능성을 기준으로 최대 다섯 개를 고릅니다. 준비된 후보가 두 개 미만이면 다음 회차로 넘깁니다. 늦게 올라온 제안은 다음 회차에 검토할 수 있도록 열어 둡니다.
3. **24일부터 월말까지 · 투표.** GitHub Discussions에서 브라질리아 시간 기준 월말 23시 59분까지 투표합니다. 제안된 방식은 GitHub 계정당 한 가지 선택입니다.
4. **다음 달 초 · 결과 공개.** 득표수와 먼저 진행할 아이디어를 공개합니다. 관리자가 GitHub 제안 글에서 작성자와 직접 이야기해 목표와 테스트 내용을 정한 뒤, 테스트 대상으로 선정된 변경을 구현합니다. 같은 글에서 작업과 실제 출시 버전의 링크를 확인할 수 있습니다.

공동 1위라면 경기 영향과 실현 가능성을 검토해 결정 이유를 공개합니다. 치명적인 버그는 언제든 고칠 수 있습니다. 테스트에서 안정성, 성능 또는 밸런스 문제가 드러나면 결과와 다음 조치를 안내합니다.

**기간 한정 변경.** 게임 방식이나 메타가 크게 바뀌는 경우 릴리스 노트에 종료일을 미리 알릴 수 있습니다. 제안 글에 경기 경험을 남겨 변경을 유지할지, 수정할지, 종료할지 함께 판단해 주세요. 월간 **CHAOS META**는 큰 변화를 별도 모드에서 시험해 보는 향후 아이디어입니다.

## Português

A primeira votação será anunciada quando a enquete estiver configurada e houver pelo menos duas ideias prontas. Você precisa de uma conta GitHub para sugerir, reagir ou votar.

1. **Dias 1 a 20 · Envie ideias.** Procure primeiro nas sugestões abertas. Se a sua ideia já existir, deixe um 👍 e conte o que aconteceu em jogo. Se for nova, descreva o problema e a mudança que você quer testar. Inclua versão do mapa, modo e onda se forem relevantes.
2. **Dias 21 a 23 · Seleção.** A equipe escolhe até cinco ideias com base no apoio e na viabilidade de testar. Com menos de duas prontas, a votação passa para o ciclo seguinte. Ideias recebidas depois da seleção seguem abertas.
3. **Dia 24 até o fim do mês · Votação.** A enquete fica no GitHub Discussions até as 23h59 de Brasília do último dia do mês. A proposta é uma escolha por conta GitHub.
4. **Início do mês seguinte · Resultado.** Publicamos os totais e quais ideias entram primeiro. Vou conversar com os autores nos tópicos do GitHub para entender a intenção, combinar o que será testado e implementar as mudanças escolhidas para teste. O tópico recebe o link do trabalho e, se a mudança sair, da release.

Se houver empate no topo, a equipe considera o impacto nas partidas e a viabilidade e explica a decisão publicamente. Bugs críticos podem ser corrigidos a qualquer momento. Se os testes revelarem problemas de estabilidade, desempenho ou balanceamento, publicamos o resultado e o próximo encaminhamento.

**Mudanças por tempo limitado.** Grandes mudanças de gameplay ou de meta podem ter data de encerramento anunciada nas notas da versão. Conte como foram as partidas no tópico da sugestão para ajudar a decidir o que fica, muda ou sai. O **CHAOS META** mensal é uma ideia futura para experimentar mudanças maiores em um modo separado.

## Español

Anunciaremos la primera votación cuando esté configurada y haya al menos dos ideas listas. Necesitas una cuenta de GitHub para proponer, reaccionar o votar.

1. **Del 1 al 20 · Propuestas.** Revisa las ideas abiertas. Si alguien ya propuso la tuya, añade un 👍 y cuenta lo que pasó en tu partida. Para una idea nueva, describe el problema y el cambio que te gustaría probar. Incluye la versión del mapa, el modo y la oleada cuando sean relevantes.
2. **Del 21 al 23 · Selección.** El equipo elige hasta cinco ideas según el apoyo de la comunidad y la posibilidad de probarlas. Si hay menos de dos listas, la votación pasa al siguiente ciclo. Las ideas que lleguen más tarde quedan abiertas.
3. **Del 24 al último día del mes · Votación.** La encuesta se hace en GitHub Discussions y cierra a las 23:59, hora de Brasilia. El formato propuesto es una opción por cuenta de GitHub.
4. **A principios del mes siguiente · Resultados.** Publicamos los totales y qué ideas tienen prioridad. El responsable del mapa habla con los autores en sus hilos de GitHub para entender su objetivo, acordar qué probar e implementar los cambios seleccionados. En el hilo se añadirá un enlace al trabajo y a la versión si el cambio se publica.

Si hay un empate en el primer puesto, el equipo valora el efecto en las partidas y la viabilidad y explica su decisión en público. Los errores críticos pueden corregirse en cualquier momento. Si las pruebas revelan problemas de estabilidad, rendimiento o equilibrio, explicaremos el resultado y el siguiente paso.

**Cambios temporales.** Los grandes cambios de jugabilidad o del meta pueden tener una fecha de finalización anunciada en las notas de la versión. Cuenta tu experiencia en el hilo para ayudar a decidir si se mantienen, se ajustan o se retiran. El **CHAOS META** mensual es una idea futura para probar cambios grandes en un modo aparte.

## Français

Le premier vote sera annoncé une fois le sondage configuré et au moins deux idées prêtes. Il faut un compte GitHub pour proposer, réagir ou voter.

1. **Du 1er au 20 · Propositions.** Consultez les idées ouvertes. Si votre idée a déjà été proposée, ajoutez un 👍 et racontez ce qui s’est passé dans votre partie. Pour une nouvelle idée, décrivez le problème et le changement à essayer. Précisez la version de la carte, le mode et la vague si c’est pertinent.
2. **Du 21 au 23 · Sélection.** L’équipe retient jusqu’à cinq idées selon le soutien des joueurs et la possibilité de les tester. Si moins de deux idées sont prêtes, le sondage passe au cycle suivant. Les idées reçues plus tard restent ouvertes.
3. **Du 24 au dernier jour du mois · Vote.** Le sondage se déroule sur GitHub Discussions jusqu’à 23 h 59, heure de Brasília. Le format proposé est un choix par compte GitHub.
4. **Début du mois suivant · Résultats.** Nous publions le nombre de votes et les idées prioritaires. Le responsable de la carte échange avec leurs auteurs dans les fils GitHub pour comprendre leur objectif, convenir des essais et mettre en œuvre les changements retenus pour les tests. Le fil contient un lien vers le travail et, si le changement sort, vers la version publiée.

En cas d’égalité en tête, l’équipe évalue l’effet sur les parties et la faisabilité, puis explique publiquement sa décision. Les bugs critiques peuvent être corrigés à tout moment. Si les essais révèlent des problèmes de stabilité, de performance ou d’équilibrage, nous expliquerons le résultat et la suite.

**Changements temporaires.** Les changements importants de gameplay ou de méta peuvent avoir une date de fin indiquée dans les notes de version. Partagez votre expérience de jeu dans le fil de l’idée pour aider à décider s’il faut les garder, les ajuster ou les retirer. Le mode mensuel **CHAOS META** est une idée pour tester de grands changements dans un mode à part.
